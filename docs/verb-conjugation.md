# 동사 활용과 읽기

## 표시 위치

웹·Android·iOS의 단어 상세를 펼치면 활용 예제를 자동으로 보여준다. 학습 카드는 **정답 보기 이후**에만 활용표를 표시한다. 기존 원본 예문과 활용 예제는 별개이며 원본 본문이나 FSRS 카드를 수정하지 않는다.

세 그룹으로 최대 21종을 제공한다: 기본형, 정중형·정중 부정·정중 과거·정중 과거 부정, 부정·과거 부정·과거, て형·진행/상태·희망·정중 요청·하지 말아 주세요, 가능·수동·사역·사역 수동·의지/권유·명령·ば 조건·たら 조건. 모든 조합이나 모든 문맥의 문장을 생성한 결과는 아니다. 각 형태의 쓰임을 설명하며 명령형의 강한 어감과 가능/수동이 같은 모양인 경우를 구분한다.

## 분류와 예외

- MAX의 실제 `partOfSpeech`에 있는 5단·1단·サ변·カ변을 우선 사용한다. 명사·サ변 항목은 `する`를 붙인 동사로 보여준다. `～いる/～える`라는 끝 모양만으로 1단이라고 추정하지 않는다.
- 5단의 9개 어미, `う→わない`, て/た형 음편을 처리한다. `行く/往く/逝く`와 해당 복합 동사의 て/た형은 `って/った`, `問う/請う/乞う`는 `うて/うた`다.
- `来る`의 `くる/き/こ` 읽기를 형태마다 계산한다. `する`와 명사+する는 `します/しない/して/できる`를 사용한다.
- `ある`의 부정은 `ない/なかった`다. 일반 예제로 쓰지 않는 가능·수동·사역·사역 수동·명령·요청·금지는 진행·희망·의지형도 제외해 11종을 보여준다.
- `いらっしゃる/おっしゃる/くださる/なさる/ござる`의 정중형 어간은 `り` 대신 `い`다. 다른 형태의 어간까지 `い`로 바꾸지 않는다.
- 명사가 아닌 일부 어휘적 サ변(예: `愛する`)에는 `愛できる` 같은 잘못된 가능형을 만들지 않는다. 기본 활용 20종과 해당 안내를 표시한다.
- 읽기 불일치·미확인 분류·문장·지원하지 않는 형태에는 표를 생성하지 않는다. 웹 개인 단어는 기존 Kuromoji IPADIC 0.9.0의 정확한 단일 사전 기본형/サ변 명사를 확인해 보완할 수 있다. 서버/사전이 없는 네이티브의 분류 없는 개인 단어는 확인된 `する/来る/くる`만 지원한다.

- `くれる/呉れる`의 명령형은 `くれ`다. 일반 예제로 부적절한 가능·수동·희망·의지·てください 요청은 제외해 16종을 제공한다. 동음의 `暮れる`와 구분한다.
- `いる/居る`는 `いている`를 제외해 20종, `できる/出来る`는 가능·수동·희망·의지·명령·사역·사역 수동·요청·금지를 제외해 12종을 제공한다. `できている`는 완료/결과 상태의 쓰임이다.
- 기본 뜻에서 비의지적인 것으로 확인한 표기/읽기 조합에는 의지·명령·가능형을 생성하지 않는다. `分かる/わかる`의 가능·수동과 `知る`의 가능도 제외한다. 모든 문맥에서 불가능하다는 판정은 아니며 원본의 여러 뜻 중 일부는 다른 제약을 가질 수 있다.
- 원본 혼합 품사인 `駆ける/かける`는 확인된 현대 1단 분류를 적용한다. 그 밖의 미확인 1단/5단 혼합 분류는 거부한다. `準ずる/准ずる`는 원본 サ변임을 안내하고 검증된 현대 동의형 `準じる/准じる`의 활용으로 표시한다. 원본 카드·읽기는 바꾸지 않는다.
- `ゆく`의 て/た형은 `いって/いった`이며 사전형 읽기는 `ゆく`로 유지한다. `気がある` 등의 부정도 어간을 보존해 `気がない`로 만든다.

## 공통 계약과 발음

웹 `NoteView/CardView.verbConjugation`은 선택 필드다. `{verbClass,classLabel,dictionaryForm,dictionaryReading,rule,forms}`이며 각 form은 `{key,label,group,description,japanese,reading,stem,suffix,readingGuide}`다. `stem+suffix=japanese`; 기본형에는 바뀐 어미 강조가 없다. 그룹은 `BASIC/CONNECT/ADVANCED`다.

가나 읽기는 항상 별도 줄에 표시한다. 후리가나와 한글 발음 보조는 기존 사용자 설정을 따른다. 확인된 전체 읽기를 기존 KanaAlignment/HangulPronunciation에 전달하며 모호한 한자 분할을 강제로 만들지 않는다. `思う/拾う`의 모라 경계도 읽기 구간에서 전달해 한글 보조가 `오모우/히로우`로 일치한다. 활용형 듣기는 **계산된 가나 읽기**를 사용한다. 원형의 녹음을 활용형에 재사용하지 않는다. 웹은 선택된 Supertonic/기기 TTS, 네이티브는 설치된 일본어 기기 TTS를 사용하며 원형 음성 모드/음성 미설치 상태를 숨기지 않는다.

Kotlin의 순수 `content/domain/VerbConjugation.kt`는 Android에 빌드 시 재사용한다. Swift 포트는 직접 작성한 공통 `native/shared/verb-fixtures.json` 49개 예제와 동일해야 한다. 기존 콘텐츠 패키지의 품사·읽기를 사용하므로 MAX 재import나 DB 마이그레이션이 필요하지 않다.

## 근거와 실제 범위

규칙은 [문부과학성 동사 활용 안내](https://tsunagarujp.mext.go.jp/nihongo), [국제교류기금 활용 워크시트](https://www.irodori.jpf.go.jp/assets/data/resources/Grammar_Worksheets_Y.pdf), [국립국어연구소 기본동사 핸드북](https://www2.ninjal.ac.jp/verbhandbook/)을 확인했다. 외부 예문·그림·음성을 복제하지 않았다.

실제 개인 MAX 2.1.2 변환본의 어휘 9,159개 중 동사 품사 항목 **3,361개 전부**에 활용표를 생성하는 것을 확인했다: 5단 965·1단 491·する 1,902·くる 3. 형태 수는 위 예외 정책에 따라 다르다. 이는 어휘별 모든 형태의 청취나 모든 용법의 전문가 검수를 수행했다는 뜻은 아니다. 실행한 테스트·화면·재배포 결과는 [검증 기록](verification.md)을 따른다.

이번 전수 검사 수치와 비교 자료의 한계는 [전수 검수 결과](verb-conjugation-review.md)를 따른다.
